## Findings, ranked

Severity: **H** high (fix now), **M** medium (this iteration if cheap), **L** low / informational.

### H1 — Vizard template lock can be bypassed by direct API call ✅ FIXED

- **File**: `src/app/api/vizard/start/route.ts`
- **Bug**: Lock verification (`/api/vizard/templates/verify`) is client-side only. A user could POST `/api/vizard/start` with a locked `templateId` skipping the verify call. Server accepted any templateId.
- **Fix**: Start route now re-checks the template's `lockCode` server-side. Clients must include the matching code in the start request (admins/editors bypass).

### H2 — AI cover-art + article routes ignored active version ✅ FIXED

- **Files**: `src/app/api/ai/cover-art/route.ts`, `src/app/api/ai/generate-article/route.ts`
- **Bug**: After uploading a v2 of a video, the cover-art and article routes still read/wrote AI at the canonical v1 key. Other AI routes (transcribe, save-field, regenerate-section, status) correctly resolved to the active version's key via `activeVideoKey()`.
- **Fix**: Both routes now call `activeVideoKey(canonical)` before reading the AI sidecar.

### H3 — Vizard webhook not idempotent ✅ FIXED

- **File**: `src/app/api/vizard/webhook/route.ts`
- **Bug**: Re-delivery of the same `projectId` (e.g. Vizard's dashboard-level fallback + per-job webhook both fire) would re-download all clips, overwriting `clipsDelivered` and potentially flipping `status` back from `succeeded` to `processing`.
- **Fix**: Top-of-handler guard: if job is already `succeeded`, short-circuit with `{ received: true, alreadyDelivered: true }`.

### M1 — `/admin/revenue` is fake but says "Live numbers" ✅ FIXED

- **File**: `src/app/(admin)/admin/revenue/page.tsx`
- **Bug**: Page sources from `mockUsers`, not real Stripe data. Copy reads "Live numbers from Stripe (mocked in this scaffold)" — first half is misleading.
- **Fix**: Copy rewritten to explicitly say "Demo numbers (mock data). Real Stripe MRR coming in a later iteration."
- **Real follow-up**: Wire `/admin/revenue` to actual Stripe subscription data via API (planned future work — not done in this pass).

### M2 — Stripe customer ID not cleared on cancel

- **File**: `src/app/api/stripe/webhook/route.ts:148`
- **State**: `customer.subscription.deleted` clears `stripeSubscriptionId` but leaves `stripeCustomerId`. Re-subscribe normally works (Stripe customer still exists, just no active sub). However if customer is **deleted in Stripe dashboard** (rare admin action), the next checkout would fail trying to reuse the dead ID.
- **Decision**: Not fixed this pass. Edge case (customer deletion is rare). Document + revisit when it actually happens.

### M3 — Magic-link token race on simultaneous redemption

- **File**: `src/lib/magic-link.ts:46-61`
- **State**: `consumeMagicToken` reads → checks expiry → deletes in separate statements. Postgres default isolation (`READ COMMITTED`) means both concurrent requests could pass the check and both attempt delete; only one succeeds. The "lucky" path still grants the session twice on the same email, which is benign (same user, same email).
- **Decision**: Not fixed. Practically safe with one user clicking a link in two tabs.

### M4 — PreviewModal hides revisions for any "clip"-typed file

- **File**: `src/app/(client)/account/projects/[id]/_components/PreviewModal.tsx:105-108`
- **State**: Revisions hidden when `file.type === "clip"` OR filename starts with `clip_vizard_`. If a user manually classifies a non-Vizard file as "clip" via the move-to-clips bulk action, revisions also disappear.
- **Decision**: This is correct intent — clips of any source don't need a revision flow.

### M5 — `ONPOD_SERVICE_KEY` env var may not be set in prod

- **Files**: `src/app/api/admin/clients/invite/route.ts:42` (n8n service-token path)
- **State**: When n8n calls the invite route with `X-Onpod-Service-Key` header, code compares to `process.env.ONPOD_SERVICE_KEY`. If env unset, the header check returns false and falls through to cookie auth (which n8n doesn't have). Result: n8n calls fail with 401.
- **Action needed**: User should `vercel env ls | grep ONPOD_SERVICE_KEY` to confirm. If unset, generate a random string and add it to production + share with n8n.

### L1-L4 — Various

- **L1** Revenue/settings pages don't have a scope check — but the layout nav hides them for scoped admins, so they're only reachable by URL-typing. If a scoped admin types the URL, they see the page. Should add a `scope.studios !== null && notFound()` gate.
- **L2** `getUserByEmail` lowercases input — safe against case-mixed Stripe emails.
- **L3** PaymentLinks email matching: DB enforces `emails_unique` index, so dual-account email collisions can't happen.
- **L4** `requireSession` / `requireAdmin` use Next's `redirect()` which throws — proper behavior, can't be caught accidentally.
